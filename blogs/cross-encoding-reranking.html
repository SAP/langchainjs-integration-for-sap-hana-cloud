Sharper Search Results: Cross-Encoding Reranking with SAP HANA Cloud and LangChain.js

A customer types into your product search:

“best noise canceling headphones for office work and video calls”

Vector search instantly returns four solid headphones. The order looks fine. Mostly. The AudioMax Pro 5 is on top, the QuietShield Ultra is second, an earbud sneaks into third, an audiophile reference can sits fourth. Technically all relevant. But for someone joining back-to-back Zoom calls, the ranking is a little off, because the truly “office-friendly” option isn’t first.

That’s the gap cross-encoding reranking closes. With @sap/hana-langchain’s HanaReranker, you let a more sophisticated model take a second look at your top candidates and put them in the order your customer actually wants.

Full walkthrough on GitHub: blogs/cross-encoding-reranking.md. Every code sample, every score, and the full benchmark breakdown.

Why two stages beat one

Vector search is fast because it’s a bi-encoder: the query and each document are encoded into vectors independently, then compared with a single dot product. Brilliant at scale, but blind to the subtle interactions between query and document.

A cross-encoder reads the query and the document together, token by token, and asks “how relevant is this specific document to this specific query?” Slower per pair, dramatically more accurate.

The winning pattern combines both:

User Query
    │
    ▼
┌─────────────────────┐
│  Vector Search      │  Fast, approximate
│  (Bi-encoder)       │  Returns top 20 candidates
└─────────────────────┘
    │
    ▼
┌─────────────────────┐
│  Cross-Encoder      │  Slower, precise
│  Reranking          │  Returns top 5 best matches
└─────────────────────┘
    │
    ▼
Final Results (highly relevant)

Cast a wide net cheaply, then let the smarter (and pricier) model pick the actual winners.

The headphones story, with and without reranking

Same six-product catalogue. Same query: “best noise canceling headphones for office work and video calls”. First, plain vector search: 

Vector Search Results (may not be optimally ordered):
  1. AudioMax Pro 5
  2. QuietShield Ultra
  3. AudioMax Buds 5
  4. StudioRef HD 560

Now we plug in HanaReranker. Two-stage retrieval is one extra line: 

import { HanaReranker } from "@sap/hana-langchain";

const reranker = new HanaReranker(client, "SAP_CER.20250701");
await reranker.initialize();

// Stage 1: cast a wide net with vector search
const candidates = await productStore.similaritySearch(searchQuery, 6);

// Stage 2: let the cross-encoder reorder for precise relevance
const reranked = await reranker.rerank(candidates, searchQuery, 4);

Reranked Results (optimized for "office work and video calls"):
  1. QuietShield Ultra (relevance: 0.52)
  2. AudioMax Buds 5 (relevance: 0.46)
  3. AudioMax Pro 5 (relevance: 0.42)
  4. StudioRef HD 560 (relevance: 0.05)

Look at what happened. The QuietShield Ultra, whose description specifically calls out “world-class noise cancellation”, jumps to the top. The reference-grade StudioRef, perfect for music but irrelevant for calls, gets pushed down with a near-zero score. The cross-encoder didn’t just “find similar text.” It understood the job the customer was hiring the headphones to do.

Reranking inside a single call

Don’t want to manage two stages by hand? Pass a RerankConfigOptions straight into similaritySearch and the library does both behind one method call: 

import { RerankConfigOptions } from "@sap/hana-langchain";

const rerankConfig: RerankConfigOptions = {
  modelId: "SAP_CER.20250701",
  topN: 3,
};

const results = await productStore.similaritySearch(
  "noise canceling headphones for travel",
  6,         // pull 6 candidates internally
  undefined, // no metadata filter
  undefined, // no callbacks
  rerankConfig,
);

You hand it the query, it hands you back the top three, already reranked and already wrapped as Document objects, ready for your UI or LLM prompt.

Boosting accuracy with metadata-aware reranking

What about “affordable wireless headphones with long battery”? Pure content-based reranking can miss the point, because the word “affordable” doesn’t live in any product description. But the TuneCore 510 is literally “budget-friendly” with “40-hour battery life” in its name and category metadata.

Tell the reranker to score against those fields too:

const rerankConfig: RerankConfigOptions = {
  modelId: "SAP_CER.20250701",
  topN: 3,
  rankFields: ["name", "category"], // include in scoring
};

[
  { name: 'TuneCore 510',  price:  49.99 },   // jumps to #1 thanks to "affordable" + 40-hour battery
  { name: 'AudioMax Pro 5', price: 349.99 },
  { name: 'AudioMax Buds 5', price: 299.99 }
]

The budget TuneCore, easy to overlook in pure content scoring, leaps to first place. Especially powerful when you have structured relevance signals: brand names, categories, tags, SKU prefixes.

One more drop-in: the document compressor pattern

HanaReranker implements LangChain’s BaseDocumentCompressor interface, so it slots cleanly into existing retrieval pipelines: 

const candidates = await productStore.similaritySearch("best headphones for music", 4);
const compressed = await reranker.compressDocuments(candidates, "best headphones for music production");

And the “music production” query surfaces the StudioRef HD 560, with its “critical listening and mixing” description, right where it belongs: 

[
  { name: 'StudioRef HD 560', relevance_score: 0.57 },   // music producer's pick
  { name: 'AudioMax Pro 5',    relevance_score: 0.35 },
  { name: 'QuietShield Ultra',      relevance_score: 0.20 },
  { name: 'TuneCore 510',     relevance_score: 0.18 }
]

Each result comes back with its relevance_score tucked into metadata, handy for UI badges, threshold filtering, or downstream re-weighting.

The cheat sheet

  • Retrieve more, rerank fewer. 20 to 30 candidates narrowed down to a top 5 is a sweet spot for real-time search. The wider the net at stage 1, the more raw material the cross-encoder has to work with.
  • Pre-filter with metadata. If you can narrow the candidate set with a category or in_stock filter before reranking, you save cross-encoder cycles for the documents that actually matter.
  • Use rankFields when names and tags carry meaning. Product names, document titles, and category labels often hold the signal that pure body text misses.
  • Especially valuable for RAG. Feeding an LLM the top three reranked passages instead of the top three vector hits is one of the highest-leverage upgrades you can make to answer quality.
